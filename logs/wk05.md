## Challenges I faced
The challenge I faced relates to the code above. I actually tried "while Decision_Kulu != 'y' **or** Decision_Kulu != 'n':" first which made sense in my head for a natural language translation but didn't pan out right. I wanted the while loop to only happen if the user didn't use [y/n]. 

If I left the logical operator to be OR, the condition the while loop would read if the user DIDN'T input [y/n] would be ***"while TRUE or TRUE: (so go through the loop)"***. 

If the user did inputted one of the *right* inputs like "y" for example, the condition would've read ***"while FALSE or TRUE: (One of the conditions is still true, so go through the loop)"***. 

When I used an AND operator, the conditon would read like this if I didn't input the right things, ***"while TRUE and TRUE: (Both conditions are met and the result is TRUE, so go through the loop)"***.

When inputting the right input like "y" then, ***"while FALSE and TRUE: (Both conditions have NOT been met, so DON'T go through the loop)"***.

The key thing I learned here is that while loops only run if the condition is TRUE, so that really makes me rethink how to make my statement True or not.
